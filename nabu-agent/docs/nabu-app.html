Help & guide

How a run works, what the map shows, and where a human stays in charge.

Working the live map

  • Click a node → its detail (ports · proto · product · version · CVE · CVSS · evidence · fix) + the attack path from the entry, in gold.
  • Shift-click two nodes → the path between them; C copies a pinned path.
  • Double-click a node → add a note (persists; dashed gold ring).
  • Search highlights matches; ▢ Region groups the search matches into an annotated area.
  • ▶ Replay re-plays the whole run from scratch.

The run workspace

  • Service tree (left) lists every discovered host + service; ★ marks a suggested action. Click to focus it on the map.
  • A node's drawer carries its Actions (the command builder — Run for attacker-side, Copy for victim-side, with tier + port + source) and its References (HackTricks + Exploit-DB).
  • Findings — every parsed/entered finding, strongest-first, click-through to the map. Credentials — the looted vault, shown in full.
  • Attack gate — agents propose exploitation checkpoints; you Approve / Deny. Nothing runs until you do.
  • Catalog — the full 3,190-action decision-aid, ranked ★ against what this run found; filter or search it.
  • Report — the Obsidian-compatible attack-path report, regenerate + export.

Agents

The Agents tab shows the whole agent hierarchy — orchestrator → phase agents → sub-agents. Search for one or click it in the tree/chart to tweak its role, model, autonomy, techniques, tools and system prompt. Guardrails (scope-checking, the human attack-gate, audit) stay enforced and can't be edited off.

Safety

Recon is automated; attacks are never automatic. Any spray/exploit is only ever proposed and must be approved by a human at the gate. Every target is checked against the project's authorized scope, and every action is audited.
