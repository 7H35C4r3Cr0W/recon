How each box actually gets done

For your manager — this is the loop I run on every machine. It is not "watch a walkthrough." Each box is a live field test of the tool that ends in code changes, a re-test, and a git commit.

"Completed" means

Recon and attack were driven against the live box — validated end to end, foothold→root where practical — with the tool's own modules proving they parse and behave correctly (pass/fail), not just a walkthrough read.

The goal

Turn every box's lessons into reusable, exam-legal recon/attack automation — so the tool gets sharper each machine, builds muscle memory, and (next) becomes the agent workflow above.

The through-line: a box is never "done" until a real gap it exposed is fixed in the tool, the fix is re-tested green (four gates: types, tests, lint, format), and it's committed to GitHub. That's why the same http/ftp/snmp bugs never came back — each box hardens the engine for the next one.
