From one tool to an agent swarm

Today Nabu is a single desktop app that runs a fixed recon pipeline. This is the blueprint for the next step: decompose it into small, single-purpose agents — each an LLM (Opus) with its own prompt, tools, and one job. The chain is linear until Discovery; then Routing fans out to one specialist agent per discovered service — Web, SMB/AD, FTP, SSH, DNS, LDAP, SNMP, Database, or a Generic probe — which run in parallel and converge on a scope gate. Below: each agent's stack, the typed data it hands the next, and how the system stays reliable — redundancy and error handling at every edge.

Reliability — how it stays up

An agent swarm is a distributed system, so it's designed like one: assume every agent, tool, and LLM call can fail, and make failure cheap.

⟳ Retries & idempotency

Every message carries an attempt and an idempotency_key. Transient failures retry with exponential backoff; because writes dedupe on the key, a retry never double-runs a scan or double-writes a finding.

⟳ Fan-out & isolation

Only discovered ports spawn a specialist, and they run in parallel, blind to each other. One crashing or hanging specialist is timed out and skipped — the rest keep going, and its partial output still flows.

⟳ N-of-M voting

For the two calls that must not hallucinate — the Scope gate's allow/block and the Critic's verify — several independent LLM passes vote. A command runs, or a finding survives, only on a majority.

⟳ Fallbacks & fail-closed

Deterministic logic sits behind every LLM. If the model errors or is unsure, a hard rule decides — and the gate's default is BLOCK. Enrichment is offline-first: a network failure falls back to the vendored snapshot.

⚠ Never fail silently

"Tool ran but produced 0 findings" (parser drift) raises a loud warning and keeps the raw output. A missing tool logs [missing] and continues with an alternative. Nothing is dropped quietly.

⚠ Dead-letter & escalate

A message that fails all retries goes to a dead-letter queue and the Orchestrator re-plans (skip the service, downgrade the scan, or finish with a partial report) rather than hanging the run.

⚠ Circuit breakers

A tool that keeps failing (or a host that's down) trips a breaker — the swarm stops hammering it, marks that branch degraded, and routes around it.

⚠ Checkpoint · bounded loops

The blackboard is checkpointed to disk after each step, so a crashed run resumes where it stopped. The Critic loop has a hard iteration cap, so the workflow always converges to a report.

Phase 2 — where new agents plug in

The bus + blackboard design exists so you add capability by adding an agent, never by rewiring. There are exactly three plug-in points — and the Scope Gate still governs every one of them, so the run stays in-scope and on-objective however the swarm grows.
