From one tool to an agent swarm

Today Nabu is a single desktop app that runs a fixed recon pipeline. This is the blueprint for the next step: decompose that pipeline into small, single-purpose agents — each one an LLM (Opus) that reasons about its own job — and wire them into a chronological, top-down, agent-to-agent workflow. Every agent reads and writes one shared memory; every command it wants to run passes a safety gate; a critic decides whether to go deeper or finish.

How the architecture works

Five ideas turn a chain of prompts into a dependable system.

An LLM per agent

Each agent is a focused Opus instance with one job, its own system prompt, and only the tools it needs. Small scope = reliable reasoning and easy debugging.

Shared memory

The project folder is the blackboard. Agents don't talk directly — they read and write structured state (services, findings, creds, graph), so any agent can be retried or replaced.

Hand-off, not free-for-all

Control passes in a defined order, and each edge carries a typed payload (target → services → raw output → findings → report). Deterministic flow, inspectable at every step.

A guardrail agent

The Safety Gate sits between every agent and the shell. Nothing runs until it's judged exam-legal — the compliance guarantee holds no matter what an LLM proposes.

A critic loop

The Critic verifies claims against evidence and decides go-deeper-or-finish. That single feedback edge is what makes this a workflow that converges, not a one-shot pipeline.
