From one tool to an agent swarm

Today Nabu is a single desktop app that runs a fixed recon pipeline. This is the blueprint for the next step: decompose that pipeline into small, single-purpose agents — each one an LLM (Opus) with its own system prompt, its own tools, and one job. They pass typed messages, share one memory, and run behind a safety gate. Below: each agent's stack, the exact data it hands the next, and how the system stays reliable — redundancy and error handling at every edge.

Reliability — how it stays up

An agent swarm is a distributed system, so it's designed like one: assume every agent, tool, and LLM call can fail, and make failure cheap.

⟳ Retries & idempotency

Every message carries an attempt and an idempotency_key. Transient failures retry with exponential backoff; because writes dedupe on the key, a retry never double-runs a scan or double-writes a finding.

⟳ Fan-out & isolation

Specialist agents run in parallel and are blind to each other. One crashing or hanging specialist is timed out and skipped — the rest keep going, and its partial output still flows.

⟳ N-of-M voting

For the two calls that must not hallucinate — the Gate's allow/block and the Critic's verify — several independent LLM passes vote. A command runs, or a finding survives, only on a majority.

⟳ Fallbacks & fail-closed

Deterministic logic sits behind every LLM. If the model errors or is unsure, a hard rule decides — and the gate's default is BLOCK. Enrichment is offline-first: a network failure falls back to the vendored snapshot.

⚠ Never fail silently

"Tool ran but produced 0 findings" (parser drift) raises a loud warning and keeps the raw output for review. A missing tool logs [missing] and continues with an alternative. Nothing is dropped quietly.

⚠ Dead-letter & escalate

A message that fails all retries goes to a dead-letter queue and the Orchestrator is notified; it re-plans (skip the service, downgrade the scan, or finish with a partial report) rather than hanging the run.

⚠ Circuit breakers

A tool that keeps failing (or a host that's down) trips a breaker — the swarm stops hammering it, marks that branch degraded, and routes around it.

⚠ Checkpoint & resume · bounded loops

The blackboard is checkpointed to disk after each step, so a crashed run resumes where it stopped. The Critic loop has a hard iteration cap, so the workflow always converges to a report.
